# Регулярные задачи: календарь управляющего

## Установка

1. Применить в Supabase SQL Editor `supabase/migrations/20261001010000_recurring_calendar.sql` после миграций Telegram. Миграция выполняется одной транзакцией. Она не создаёт реальные правила или задачи и не изменяет Auth.
2. Развернуть изменения интерфейса. До применения миграции интерфейс показывает существующие правила и сообщение об обновлении; импорт и редактирование новых правил недоступны.
3. Войти владельцем: **Регулярные → Набор задач управляющего**, выбрать управляющего, проверить состав, нажать **Добавить набор**. Создаются 30 правил одной операцией. Повторное добавление этого набора для того же исполнителя не создаёт дублей. Ранее введённые вручную похожие правила нужно проверить и при необходимости приостановить.
4. **Календарь** показывает расписание по месяцам, созданные задачи и их статусы. Владелец видит все правила, сотрудники — назначенные им. Для каждого правила доступны редактирование и приостановка владельцем.

Существующий Cron `nu-recurring-monthly-tasks` остаётся: `0 3 * * *` (08:00 Екатеринбург). Он вызывает `nu_generate_recurring` для текущего и следующего месяца. Новые задачи создаются в дату первого уведомления; будущие сроки заранее видны в календаре. Если правило добавлено после сегодняшнего запуска, оно обработается следующим утром, пока его дедлайн ещё не прошёл. Уведомления отправляет уже настроенный минутный Telegram-dispatcher; фактическая доставка зависит от очереди/Telegram и может быть чуть позже 08:00.

## Согласованные правила

Все дедлайны — 23:59 по Asia/Yekaterinburg. Для сроков без указанной даты уведомления выбран отступ 2 дня.

| Задача | Повтор / дедлайн | Первое уведомление |
|---|---|---|
| Контроль персонала; финансовая отчётность | ежедневно | в тот же день |
| Посещение НУ | воскресенье | пятница |
| Табак; напитки | среда | понедельник |
| РМ | вторник | воскресенье |
| Собрания | 10-е | 8-е |
| Генеральная уборка НУ1; НУ3 | последний день нечётного месяца | 1-е |
| Генеральная уборка НУ2; НУ4 | последний день чётного месяца | 1-е |
| Инвентаризация | 10-е | 1-е |
| KPI | 11-е; 21-е | 10-е; 20-е |
| График смен | последняя суббота | вторник за 4 дня до неё |
| НУ1 КУ | 15-е | 14-е |
| НУ1 аренда | последний день | предпоследний день |
| НУ2 показания | 26-е | 23-е |
| НУ2 аренда | 13-е | 11-е |
| НУ2 электроэнергия | 10-е; 20-е; 26-е | 9-е; 19-е; 25-е |
| НУ2 КУ | 26-е | 24-е |
| НУ3 показания | последний день | последний день |
| НУ4 показания | 20-е | 20-е |
| НУ4 аренда | 3-е | 1-е |
| НУ4 КУ | 12-е; 18-е; 25-е | 11-е; 17-е; 24-е |
| Отчёты и аналитика | 1-е следующего месяца | за 2 дня до конца отчётного месяца |

Проверки ежедневных задач перечислены в описании. Отчёт о выполнении — в комментарии. Интерактивные отметки каждого пункта отдельно не добавляются этой миграцией.

## Совместимость и проверки

- Существующие задачи сохраняются. Дни напоминаний сохраняются в экземпляре задачи, поэтому редактирование шаблона не меняет уже созданные задачи.
- Ключ экземпляра — дата исходного дедлайна, а не месяц; перенос дедлайна не создаёт дополнительный экземпляр.
- Удаление задачи оставляет запись экземпляра с `task_id=null`, чтобы Cron не восстановил удалённую задачу. В календаре отображается «Удалена владельцем».
- В день создания регулярной задачи сообщение о новой задаче заменяет отдельное напоминание, если оно уже стоит в очереди или отправлено. Просрочки продолжают отправляться существующим механизмом.
- RLS на шаблонах сохранён; экземпляры доступны только пользователям, которым доступен соответствующий шаблон.

Проверки:

```sh
npm run build
NU_PGLITE_PATH=/absolute/path/to/@electric-sql/pglite/dist/index.js node scripts/test-recurring.cjs
node scripts/test-telegram-routes.cjs
NU_PGLITE_PATH=/absolute/path/to/@electric-sql/pglite/dist/index.js node scripts/test-telegram-sql.mjs
```

Новый тест сравнивает SQL-календарь и UI-календарь для всех 30 правил на 48 месяцев (2026–2029), проверяет високосный февраль, чётность, последний вторник перед субботой, переход года, границу 08:00, повторный запуск, удаление, Telegram-дедупликацию и запреты RLS для управляющего/другого сотрудника/отключённого владельца.
