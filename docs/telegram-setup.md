# Telegram для «Не Усложняй»

## Настройка

1. Создать бота в официальном @BotFather командой `/newbot`.
2. В Vercel → Project → Settings → Environment Variables → Production добавить:
   - `TELEGRAM_BOT_TOKEN`: токен от BotFather, без пробелов.
   - `TELEGRAM_BOT_USERNAME`: username бота без `@`.
   - `TELEGRAM_WEBHOOK_SECRET`: случайная строка 32–256 символов (буквы, цифры, `_`, `-`).
   - `TELEGRAM_DISPATCH_SECRET`: другая случайная строка, минимум 32 символа.
   - `APP_URL`: `https://nextjs-boilerplate-nu-team2.vercel.app`.
   - `SUPABASE_SECRET_KEY` уже используется приглашениями; оставляем серверной.
3. Применить `supabase/migrations/20260930010000_telegram.sql` в Supabase SQL Editor.
4. После проверки Preview слить PR и дождаться успешного production deployment.
5. Войти owner → Telegram → «Подключить бота к платформе».
6. Каждый сотрудник в своём аккаунте нажимает «Подключить Telegram», открывает персональную ссылку и нажимает «Запустить». Ссылка действует 10 минут. Повтор webhook с тем же токеном и чатом безопасен; чужой чат не может повторно использовать токен.
7. Нажать «Проверить подключение» → «Тестовое сообщение».
8. В Supabase включить pg_net. Через Vault создать секрет `nu_telegram_dispatch_secret` со значением `TELEGRAM_DISPATCH_SECRET` из Vercel. Значения не присылать в чат и не помещать в GitHub/SQL-файлы.
9. Выполнить `supabase/migrations/20260930020000_telegram_schedule.sql` отдельно. Диспетчер запускается каждую минуту; напоминания формируются после 08:00 Екатеринбурга.

## Поведение

- Только личные чаты, привязанные через авторизованную платформу.
- Новые задачи, изменения, комментарии, запросы и решения по переносам направляются подключённым сотрудникам, имеющим доступ к задаче. Автор собственного действия не получает его уведомление.
- Напоминания исполнителю: у регулярных задач — дни из правила, у остальных — за 2 дня и в день срока. Просрочки — ежедневно исполнителю и owner. Задачи на проверке не напоминаются исполнителю; owner получает просрочки до завершения.
- Выполненные задачи не получают напоминаний. Изменённый срок отменяет старые напоминания в очереди.
- Перед отправкой перепроверяются активность, доступ и Telegram-привязка. Кнопка открывает карточку с обычной авторизацией и RLS.
- Очередь использует блокировки и аренду, до 6 попыток с паузой. При редком сбое между доставкой в Telegram и подтверждением в БД повторная доставка возможна: Telegram sendMessage не имеет idempotency key.
- Отключение отменяет ожидающие сообщения. Блокировка бота даёт failed; после разблокировки доступны новые уведомления и тест.
- Preview не регистрирует webhook и не запускает диспетчер production бота.

## Проверка перед завершением этапа

- Сборка и Vercel Preview успешны.
- Неверные webhook/dispatch secrets → 403; connect/setup/test без сессии → 401.
- Привязка, истечение/повтор ссылки, отключение и повторное подключение.
- Создать задачу другому сотруднику → сообщение с открывающейся карточкой.
- Изменить статус, комментарий, запросить/решить перенос → соответствующие сообщения.
- Отключить сотрудника/изменить назначение до отправки → недоступные сообщения не доставляются.
- Проверить cron.job_run_details и net._http_response: успешный Cron означает выполнение SQL, а результат HTTP нужно проверять отдельно.

## Локальные проверки

- `node scripts/test-telegram-routes.cjs` — проверки серверной авторизации и подавления недоступных уведомлений.
- `npm install --prefix /tmp/nu-telegram-sql-test @electric-sql/pglite --no-save --package-lock=false`
- `NU_PGLITE_PATH=/tmp/nu-telegram-sql-test/node_modules/@electric-sql/pglite/dist/index.js node scripts/test-telegram-sql.mjs` — реальный PostgreSQL в изолированной памяти, без подключения к production.
- `npm run build` — основная сборка. В сетево ограниченном окружении отдельно проверена webpack-сборка с локальным mock Google Fonts; mock в репозиторий не включён.
